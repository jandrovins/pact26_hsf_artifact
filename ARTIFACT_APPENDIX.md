# Artifact Appendix

Paper: *HSF: A Hierarchical Scheduling Framework for Application-Tailored
Scheduling on Tasking Runtimes* (PACT'26).

## Abstract

This artifact provides the five benchmarks (Cholesky, Heat, HPCCG, Matmul,
Multisaxpy), the "Sched-Stress" task-overhead microbenchmark, and the build,
launch, collection and plotting scripts used to produce the paper's figures. The
complete software stack — the OmpSs-2 affinity compiler (`clangOmpss2`), the
nOS-V and NODES runtimes, the HSF taskgroup library (`tglib`), and AMD
BLIS/libFLAME — is provisioned reproducibly with Nix flakes pinned to public
sources. The artifact regenerates the normalized-performance and geometric-mean
speedup figures that support the paper's central claim: a **1.84× geometric-mean
speedup on large problems** for HSF over the best OmpSs-2 + parallel-init
baseline. A SLURM-free smoke test builds the stack and runs a small Cholesky for
both the baseline and HSF on any x86-64 Linux host; the full paper numbers
require a dual-socket AMD EPYC 9684X (Genoa-X) node.

## Description

### How to access

Clone `https://github.com/jandrovins/pact26_hsf_artifact` or download the
Zenodo archive (DOI above). All dependencies are fetched by Nix from public
GitHub at pinned revisions (see the dependency table in `README.md`).

### Hardware dependencies

- **Reproduced badge:** dual-socket AMD EPYC 9684X (Genoa-X), 2×96 cores, 8 NUMA
  nodes, stacked L3 (CCD) — the topology the scheduling policies exploit.
- **Functional badge:** any x86-64 Linux host.

Reviewers without Genoa-X hardware can be granted **remote SSH access** to a
Genoa-X node for the Reproduced step; contact the authors via the submission
system.

### Software dependencies

Only **Nix (with flakes)** must be installed on the host. Everything else —
compiler, runtimes, BLAS/LAPACK, Python plotting stack — is pinned and built by
the flakes (`hsf/`, `nosvorig/`, `baseline/`). No SLURM is needed for the smoke
test; the full sweep uses SLURM (`sbatch`).

### Data sets

None external — inputs are generated by the benchmarks from the size parameters.

## Installation

```bash
git clone https://github.com/jandrovins/pact26_hsf_artifact.git
cd pact26_hsf_artifact
# Build/enter a dev shell (first run compiles the toolchain from source):
nix develop ./hsf --command true        # HSF stack
nix develop ./nosvorig --command true   # OmpSs-2 baseline stack
nix develop ./baseline --command true   # external OpenMP/BLAS stack
```

## Experiment workflow

1. **Smoke test (Functional):** `bash run_local.sh` — builds and runs one small
   Cholesky for baseline and HSF locally (no SLURM).
2. **Full run (Reproduced):** `HSF_ARCH=znver4 NREPS=3 bash launch_all.sh` on a
   Genoa-X SLURM cluster.
3. **Collect:** `python collect_results.py` → `summary.csv` per variant.
4. **Plot:** `python plot_reproduced.py [--no-usetex]` → `fig/*.pdf`,`.png`.

## Evaluation and expected results

The regenerated figures should match the committed `fig/*`:

- `benchmark_comparison(.pdf/.png)` — normalized performance, 2×5 grid.
- `benchmark_comparison_external_baseline` — normalized to the external baseline.
- `benchmark_speedup_geomean` and `benchmark_speedup_geomean_init` — the
  per-benchmark geometric-mean speedups; the large-problem geomean of the latter
  is ≈**1.84×**, the paper's headline claim.

On Genoa-X, expect HSF to match or exceed all baselines across benchmarks and
scales. On other hardware the pipeline completes and produces figures, but the
speedup magnitudes will differ (see "Claims not supported" in `README.md`).

## Experiment customization

- `HSF_ARCH` — build target arch (`native` default; `znver4` for Genoa-X).
- `NREPS` / `NRUNS` — repetitions for the benchmark sweep / overhead sweep.
- `PARTITION`, `ACCOUNT`, `QOS`, `TIMELIMIT` — SLURM submission parameters.
- Per-benchmark problem sizes / policies live in each
  `*/launcher_reproduce.sh` (`EXPERIMENTS` / `CONFIGS` arrays).

## Notes

- The first Nix build from source is long; a binary cache (e.g. Cachix) can be
  added to skip it.
- Transient `warning: unable to download … narinfo` messages are harmless Nix
  substituter timeouts; the build falls back to source.

## Methodology

Reproduction follows the ACM artifact-review methodology. Badges targeted:
*Artifacts Available* (public GitHub + Zenodo DOI), *Artifacts Evaluated —
Functional* (builds and runs via the smoke test and full pipeline), and
*Results Reproduced* (paper figures regenerated on Genoa-X hardware, available
to reviewers via remote access).
